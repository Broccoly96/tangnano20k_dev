# FPGA UART Debug Log System 要求定義書（Ver.1.0）

## 0. 目的

* FPGA（DUT）からホストPCへ、デバッグ情報/ログを**低LUT消費**で高密度に送出する。
* DUTの動作状態・イベント発生を、ホスト側ツールでデコード・可視化できるようにする。
* UART 1本で、ログ送出および最小限のCLI操作（ヘルプ/ソフトリセット/ログ切替）を提供する。


## 1. 制約・前提

* LUT目標：**1000 LUT以内**、デッドライン：**2000 LUT**
* UART：8N1
* ボーレート：**115200 bps（デフォルト）**

  * RTLは合成時パラメータ変更でボーレート変更可能（運用中の動的変更は不要）
* ログは**バイナリ固定長イベント**とし、文字列整形はホストPC側で行う。


## 2. 全体アーキテクチャ

### 2.1 データフロー

* **ログ（DUT→PC）**

  * Log Source（各モジュール） → LogTap（4-deep FIFO） → LogAggregator（選択式） → UART TX → PC
* **コマンド（PC→DUT）**

  * PC → UART RX → Command Decoder → 制御（log_src_sel更新/ヘルプ/ソフトリセット）

### 2.2 選択式ログ（構成案A）

* `log_src_sel` により**同時に出力するログ生成元は1つのみ**とする。
* 未選択のログ生成元は**ログ生成を行わない**（LogTapへの投入も行わない）。
* `log_src_sel` は UARTコマンドにより変更可能。


## 3. ログイベント仕様（固定フォーマット）

### 3.1 イベント長

* **1イベント = 16バイト固定（128bit）**

### 3.2 イベント構造（PAYLOAD=16B）

* PAYLOADは **4×32bit word** として定義する。
* **UART送信順（バイト順）**：Word0のLSB→MSB、次にWord1…（= little-endian送信）

  * 例：Word0[7:0] → Word0[15:8] → Word0[23:16] → Word0[31:24] → Word1…

#### Word割当

* Word0（32bit）

  * [31:24] `src_id` : ログ生成元ID（0..255）
  * [23:16] `event_id`: 生成元内イベントID（0..255）
  * [15:0]  `timestamp`: 16bitタイムスタンプ（後述）
* Word1（32bit） `arg0`
* Word2（32bit） `arg1`
* Word3（32bit） `arg2`

未使用のargは0埋め可。

### 3.3 timestamp仕様

* 16bitフリーランカウンタ（wrap-aroundあり）。
* タイムベース：1ms tick（推奨）
* リセット時は0クリア。


## 4. UARTフレーミング仕様（レベル2）

### 4.1 目的

* 同期復帰、破損検出、欠損検出を可能にする。

### 4.2 フレーム構造（ログ/CLI応答共通）

1フレームは以下で構成する：

| フィールド | サイズ | 説明                            |
| ---------- | -----: | ------------------------------- |
| SYNC       |     1B | 固定 `0x7E`                     |
| SEQ        |     1B | 連番（0..255でwrap）            |
| PAYLOAD    |    16B | 本仕様のログイベント（固定16B） |
| CRC8       |     1B | 破損検出                        |

* 1フレームの総バイト数：**19B**

### 4.3 CRC8仕様（確定）

* CRC種類：**CRC-8/ATM**

  * poly = **0x07**
  * init = **0x00**
  * refin = **false**
  * refout = **false**
  * xorout = **0x00**
* 計算対象：`SEQ` + `PAYLOAD`（SYNCは含めない）
* バイト順：UART送信順（SEQ→PAYLOAD[0]→…→PAYLOAD[15]）

### 4.4 同期復帰

* ホスト側は `0x7E` を起点にフレーム境界を探索し、CRC8一致で有効フレームと判定する。


## 5. UARTボーレート仕様

### 5.1 変更方針

* ボーレートは運用時固定とする（動的切替は不要）。
* RTLは合成時にボーレートを変更できるよう、以下のパラメータを提供する。

### 5.2 パラメータ

* `parameter int CLK_HZ  = <target clock>;`
* `parameter int BAUD    = 115200;`
* `localparam int BAUD_CNT = (CLK_HZ + (BAUD/2)) / BAUD;`  （丸め込みの例。実装は同等の整数化で可）
* RXはstart検出後、`BAUD_CNT/2` を待ってビット中心でサンプルし、その後 `BAUD_CNT` 間隔でサンプルする。


## 6. LogTap（ログ生成元アダプタ）仕様

### 6.1 目的

* 各モジュールに“ポン付け”可能な共通ログ出力機構を提供する。
* 選択されたログ生成元のイベントを、LogAggregatorへ流す。

### 6.2 バッファ

* **4-deep FIFO**（1エントリ=16Bイベント）
* FIFOがFullの際にイベント投入が発生した場合：

  * イベントはドロップする（取りこぼしは許容）
  * **ドロップ通知イベント（EV_DROP）は実装しない**

> 注：取りこぼし可視化は今後の拡張として扱い、本版では仕様外とする。

### 6.3 インターフェース（LogTap → LogAggregator）

* **AXI-Stream互換（最小サブセット）**として以下を用いる。

  * `TVALID`
  * `TREADY`
  * `TDATA[127:0]`
* **1イベント = 1beat**（TDATA=16B固定）。`TLAST` は使用しない。


## 7. LogAggregator仕様（選択式）

### 7.1 機能

* `log_src_sel` に基づき、選択されたLogTapからのみイベントを受け取り、UART送出する。

### 7.2 切替適用条件

* `log_src_sel`変更要求を受けても、**適用はイベント境界**で行う（フレーム途中で切替しない）。

  * イベント境界：16Bイベント（1beat）をpopし、UART送出用にラッチした後に次状態へ移るタイミング

### 7.3 切替通知（必須）

* 切替適用時に必ず「切替通知イベント」を1件送出する。
* 送出形式は通常ログイベントと同じ（PAYLOAD=16B）。


## 8. CLI（最小コマンド）仕様

### 8.1 コマンド一覧（UART RX）

* `?`（0x3F）：ヘルプ表示
* `Ctrl+R`（0x12）：ソフトリセット
* `Ctrl+F`（0x06）：次のログ生成元へ切替（`log_src_sel++` wrap）
* `Ctrl+D`（0x04）：前のログ生成元へ切替（`log_src_sel--` wrap）

### 8.2 応答方式（重要）

* CLI応答は、**専用TYPEを設けず**、すべて「予約 `src_id` のシステムイベント」として送出する。
* これにより、UARTフレームは常に固定長（19B）となり、ホスト側の同期処理を単純化する。

### 8.3 システム予約ID

* `src_id = 0x00` を **System/CLI予約**とする。
* `event_id` は以下を予約する（追加は将来拡張で可）。

  * `0x01`：`EV_MODE_CHANGE`（log_src切替通知）

    * arg0 = old_sel（下位8bit有効、他0）
    * arg1 = new_sel（下位8bit有効、他0）
    * arg2 = 0
  * `0x02`：`EV_HELP`（ヘルプ）

    * arg0..arg2：ASCIIメッセージ（12byte）を格納（不足分は0）
  * `0x03`：`EV_RESET_ACK`（リセット受付）

    * arg0 = 0（将来拡張用）
    * arg1 = 0
    * arg2 = 0

> ASCII格納のバイト順は、各argワードのlittle-endian（LSBが先）とする。

### 8.4 ヘルプ内容（最低限）

* `EV_HELP` を複数回送出してよい（最大行数は実装裁量）。
* 最低限、以下の情報を含める：

  * `? help`
  * `^R reset`
  * `^F next log`
  * `^D prev log`

### 8.5 ソフトリセット

* `Ctrl+R`受理後、DUTが所定のリセット動作を行う。
* リセットの定義：本要件では「DUT内部ロジックを初期状態へ戻す」こと。詳細なリセット範囲は実装仕様で規定する。


## 9. ログ生成元数と選択（案6-A）

### 9.1 ログ生成元数

* `parameter int NUM_SRC = <N>;`（プロジェクトに合わせて設定）
* `localparam int SEL_W = (NUM_SRC <= 1) ? 1 : $clog2(NUM_SRC);`

### 9.2 `log_src_sel` の有効範囲

* `log_src_sel` は **0..NUM_SRC-1** を有効とする。
* `SEL_W` の端数により `2^SEL_W > NUM_SRC` となる場合でも、無効値（NUM_SRC..2^SEL_W-1）へ遷移しないように実装する（スキップ）。
* **OFFモードは設けない**（常にいずれか1つが選択される）。

### 9.3 wrap規則

* Ctrl+F（次）：`sel = (sel == NUM_SRC-1) ? 0 : (sel + 1)`
* Ctrl+D（前）：`sel = (sel == 0) ? (NUM_SRC-1) : (sel - 1)`

### 9.4 デフォルト

* リセット後のデフォルトは `log_src_sel = 0` とする。


## 10. ID管理（src_id/event_id）

* `src_id` はモジュール単位にユニーク。
* `event_id` は `src_id` ごとのローカル番号で良い。
* 管理方法（推奨）：

  * FPGA側：SV package等で `src_id` / `event_id` を集中定義
  * ホスト側：JSON/YAML辞書で `(src_id,event_id)` → 表示フォーマットへマップ


## 11. ホスト側（参考要件）

受信デコーダは以下を実装できること：

* SYNC探索による同期復帰
* SEQによる欠損検出（SEQの不連続を通知）
* CRC8による破損検出
* PAYLOAD(16B)のデコード（本仕様のエンディアンに準拠）
* `(src_id,event_id)` をキーにした表示展開（辞書）


## 12. テスト条件（次工程で規定）

* 連続送信時の同期維持（CRC/SEQ）
* log切替のイベント境界適用（フレーム破損なし）
* CLIコマンド受理とSystemイベント応答
* ソフトリセット動作
